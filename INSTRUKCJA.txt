TASKPOINT — BETA 0.6 — ROLE ODCZYTYWANE Z FIREBASE
=================================================

CO NOWE:
- Logowanie Firebase e-mail/hasło.
- Po zalogowaniu aplikacja pobiera users/<uid> z Cloud Firestore.
- Bez dokumentu profilu / aktywnego konta / dozwolonej roli nie wpuszcza do aplikacji.
- Zamiast przełącznika ról widać rzeczywistą rolę zapisaną w Firebase.
- Administrator w lokalnym demo widzi wszystkie funkcje, w tym akceptacje.
- Nie zmieniono modułów: budowy, materiały, zamówienia, magazyn, transport, dokumenty.

WYMAGANE REGUŁY FIRESTORE:
- W pliku FIRESTORE-RULES-0.6.txt znajdują się bardziej restrykcyjne reguły
  niż w poprzedniej wersji: profil użytkownika może modyfikować tylko administrator.
- Wejdź w Firebase > Firestore Database > Rules, wklej CAŁY plik reguł,
  naciśnij Publish.
- Zakładają kolekcję users oraz dokument administratora o Document ID = UID
  istniejącego konta Authentication, role = admin (string), active = true (boolean).
- NIE używaj ogólnego `allow read, write: if request.auth != null`.

PUBLIKACJA NA GITHUB PAGES:
1. Rozpakuj paczkę ZIP.
2. GitHub > Klaudia399/TaskPoint > Add file > Upload files.
3. Wgraj pliki: index.html, app.js, auth.js, styles.css, sw.js,
   manifest.webmanifest, icon-192.png, icon-512.png.
4. Pliki instrukcji można także wgrać, ale nie są potrzebne do uruchomienia.
5. Kliknij Commit changes.
6. Otwórz https://klaudia399.github.io/TaskPoint/ i zaloguj się.
7. Na górze powinno być „Administrator”, a nie lista ról.
8. Jeśli przeglądarka pokazuje starą wersję, odśwież ją; stary service worker
   może w razie problemów wymagać usunięcia danych witryny.

OGRANICZENIA BEZPIECZEŃSTWA I FUNKCJONALNOŚCI:
- Rola zweryfikowana przez Firestore, ale BIZNESOWE AKCJE w aplikacji to DEMO.
- Wszystkie zamówienia, materiały, transporty, komentarze i załączniki
  nadal zapisują się w localStorage urządzenia, a nie w Firestore.
- Nie ma prawdziwego panelu zarządzania kontami, współdzielenia danych,
  automatycznych powiadomień ani przypisania budów do kierowników.
- Wersja nie jest przeznaczona do poufnych danych firmowych i produkcji.
- Firebase config w kodzie WEB jest publiczny — nigdy nie wgrywaj haseł ani
  prywatnych kluczy service account na GitHub Pages.
- Zmiana roli przez administratora w Firebase wymaga odświeżenia strony.
- Zmiany reguł i kodu realizuj najpierw na kontach testowych.
